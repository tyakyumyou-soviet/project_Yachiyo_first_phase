# Phase 3: Voice / TTS (音声合成) 完全計画・技術仕様書

## 0. 2026-05-07 改訂方針（優先）

本節は既存の詳細設計より優先する。詳細な変更仕様は ../PLAN_CHANGE_SPEC_2026-05-07.md を参照する。

- **Phase 3の役割**: Phase 4統合で使うTTSパーツの技術実証とAPI化を行う。声質R&Dは進めるが、本体MVPの必須条件にはしない。
- **第一検証TTS**: GPT-SoVITSを優先する。少量データで月見ヤチヨ/早見沙織さんにかなり近い声を再現できるかを最初に確認する。
- **第二候補TTS**: GPT-SoVITSで満足できない場合、Style-Bert-VITS2へ移行して本格学習する。
- **R&D比較枠**: F5-TTS / IndexTTS2 / VOICEVOXを比較枠に残す。
- **TTSGateway化**: `/voice` は `engine`, `voice_id`, `style`, `speed`, `format` を受け、エンジンを差し替え可能にする。
- **GPU前提**: RTX3060の専用VRAM 12GB内でLLMと同居できるかを実測する。共有GPUメモリ8GBは常用しない。
- **LLM前提**: 現行のLLM基準は `Qwen3-VL 8B` とする。ただし、リアルタイム性を重視して `Gemma 4 26B A4B + MTP` を採用する可能性を残し、TTS側は特定LLMに依存しないHTTP/WebSocket契約で統合する。
- **個人・非公開前提**: 声質R&Dは完全個人・非公開・非配布・非商用の範囲で進める。外部公開する可能性が出た場合だけ許諾済み/オリジナル声へ切り替える。

### 0.1 TTS比較枠の位置づけ

| 技術 | 位置づけ | 期待 | 注意 |
|:---|:---|:---|:---|
| GPT-SoVITS | 第一検証エンジン | 5秒zero-shot、1分few-shot、日本語対応、WebUI/前処理が強い | VRAM同居、長文安定性、API統合は実測 |
| Style-Bert-VITS2 | 第二候補/本格学習 | GPT-SoVITSで満足できない場合の本命学習。日本語品質、辞書登録、キャラクター音声学習が強い | データ品質と学習工程が支配的 |

| IndexTTS2 | 感情/時間制御比較 | 感情と話者性の分離、発話時間制御、リップシンク適性 | 重い可能性、ライセンス/日本語品質確認 |
| VOICEVOX | fallback | 安定した日本語TTS、実装容易 | ヤチヨ専用声質ではない |

## Part 1: プロダクトビジョンと機能要件（何を作るのか）

### 1. プロジェクト目標
フェーズ1（AIの脳）が生成したテキストを、早見沙織さん（ヤチヨ役声優）の声質に極めて近い音声としてリアルタイムに再生する「ヤチヨの声帯」を構築する。フェーズ3は研究開発（R&D）フェーズとして位置づけ、まず「理想の音声が出るか」を検証し、LLMとの本格連携はフェーズ4で行う。

### 2. 達成すべき品質目標
- アニメ『超かぐや姫！』で月見ヤチヨが喋っている声と聴き比べた際に、同一人物の声であると認識できる水準を目指す。
- 「ヤオヨロー！」「ツクヨミ」等の作品固有語を正確に発音できること。
- テキストの内容から感情を自然に反映できること。GPT-SoVITSで満足できる声質・表現が得られるかを先に確認し、不足する場合はStyle-Bert-VITS2の辞書・学習・表現制御を使って改善する。フェーズ1の表情/動作制御イベントはフェーズ2のアバター制御専用であり、TTS側には原則プレーンテキストのみを渡す。

### 3. 技術選定の最終決定と棄却理由

#### ✅ 第一検証: GPT-SoVITS
- **選定理由**: 5秒程度の参照音声によるzero-shot TTS、1分程度のデータによるfew-shot fine-tuningが可能で、日本語にも対応する。WebUIや前処理ツールが揃っており、少量素材で「ヤチヨ/早見沙織さん方向の声質にどこまで近づくか」を最速で試せる。
- **役割**: Phase 3の最初の検証エンジン。声質類似度、固有語、低遅延、API化、RTX3060上でのLLM同居を確認する。満足できる品質ならPhase 4のTTS本採用候補にする。

#### ✅ 第二候補: Style-Bert-VITS2 (JP-Extra)
- **選定理由**: 日本語品質、辞書機能、キャラクター音声学習の実績が強い。GPT-SoVITSで声質・安定性・低遅延のいずれかに満足できない場合、本格学習エンジンとして採用する。
- **役割**: GPT-SoVITSで足りない場合の本命学習。より多いクリーンデータを用意して、ヤチヨ声質の安定再現を狙う。

#### 🔧 補助利用: CosyVoice 3.0 (0.5B)
- **役割**: メインエンジンとしては不採用。以下の2つの補助目的でのみ使用する。
  1. **データ品質スクリーニングツール**: 収集した音声素材をゼロショットで投入し、「どの程度似るか」でデータのクリーン度を逆算・判定する。
  2. **合成データ補充（データ拡張）**: 本物の音声データが学習に必要な最低量（10分）に満たない場合に限り、CosyVoiceで不足分の合成音声を生成し、本物データと混合して学習データセットを補充する。

#### 🔎 後段比較・現時点で優先しない技術
| 技術 | 扱い |
|:---|:---|
| VOICEVOX + RVC | 2段階パイプラインの複雑性。ストリーミング自作が必要。感情制御なし |
| Fish Speech v1.5 | LLM同居が「極限操作」と複数ソースで報告。感情制御なし |
| IndexTTS2 | R&D比較枠。感情/時間制御に価値があるが、RTX3060同居負荷とWindows導入性を実測するまで本採用しない |
| Chatterbox Multilingual | 推論VRAMが重い。ストリーミング対応不明。透かし(watermark)混入 |
| Kyutai Pocket-TTS | 日本語未対応（英語・フランス語のみ） |
| LuxTTS | 日本語品質がファインチューニング前提で実用水準未達 |
| MMVC | ペアデータ（同一セリフの話者・対象ペア）作成が膨大な手間 |

### 4. セキュリティと倫理的配慮
- 学習に使用する音声素材は、個人利用・技術検証の範囲内で使用する。
- 生成された音声を公開・配布・商用利用する場合は、声優・制作会社の権利を確認する。

## Part 2: 技術仕様と実装アーキテクチャ詳細（どう作るのか）

### 5. 音声データ収集パイプライン（最重要工程）

#### 5.1 データソースと収集手順
| 優先度 | ソース | 期待されるクリーン度 | 備考 |
|:---:|:---|:---:|:---|
| 1 | インタビュー・ラジオ出演・PV等のBGMが少ない音源 | ★★★★★ | 最もクリーン。最優先で探す |
| 2 | アニメ本編の静かなシーン(BGMなし・SE少) | ★★★★☆ | 人力での選別作業が必要 |
| 3 | アニメ本編からDemucs/UVR5でBGM除去した音声 | ★★★☆☆ | 残留ノイズのリスクあり |
| 4 | CosyVoiceによる合成データ（データ拡張用） | ★★☆☆☆ | 本物が10分未満の場合のみ使用 |

#### 5.2 音声データの前処理フロー
```text
[RAW音源]
  → FFmpegで WAV 44.1kHz/16bit モノラルに統一
  → Demucs v4 (htdemucs_ft) でBGM/SE分離
  → Whisper (large-v3) で自動文字起こし
  → 人力で文字起こしを校正（誤字・タイミング修正）
  → 品質ゲート（5.3項）で合否判定
  → 合格データのみ学習データセットへ投入
```

#### 5.3 品質ゲート（合否判定基準）
学習データに投入する前に、以下の基準を**すべて満たす**ことを必須とする。
- **聴感チェック**: イヤホンで聴いた際にBGMや環境音が認識できないこと（主観評価）。
- **SNR（信号対雑音比）**: 20dB以上であること（`pyloudnorm` 等で計測）。
- **クリップ長**: 2秒〜15秒の範囲に収まっていること（長すぎる音声は分割）。
- **CosyVoiceスクリーニング**: 当該クリップをCosyVoiceにゼロショット投入し、出力音声が元話者と明らかに異なる場合はデータ品質不足と判定し除外する。

#### 5.4 目標データ量
- **最低ライン**: 10分（学習は可能だが品質が不安定になりうる）
- **推奨ライン**: 30分（感情表現の幅が広がり、安定した高品質モデルが期待できる）
- **理想ライン**: 1時間（最高品質。現実的にはここまで集めるのは困難）

### 6. Style-Bert-VITS2 学習パイプライン

#### 6.1 環境構築
```bash
# Windows (RTX 3060)
git clone https://github.com/litagin02/Style-Bert-VITS2.git
# Install-Style-Bert-VITS2.bat を実行（依存関係の自動インストール）
# または手動:
pip install -r requirements.txt
# 事前学習済みモデル (JP-Extra) をダウンロード
python initialize.py
```

#### 6.2 学習パラメータ（RTX 3060 最適化）
```yaml
model_type: "JP-Extra"
batch_size: 4          # RTX 3060(12GB)では学習時に十分な余裕があるため4を推奨
epochs: 100            # 目安。eval lossの推移を監視して早期停止する
learning_rate: 0.0001  # ファインチューニングのため低めに設定
save_every_steps: 1000 # 1000ステップごとにチェックポイント保存
eval_every_steps: 500  # 500ステップごとに評価音声を生成し品質を目視・聴覚チェック
```
- **学習所要時間の目安**: RTX 3060、バッチサイズ4、データ量30分の場合、約2〜4時間（batch_size増加分高速化）。
- **品質チェック**: `speech_mos.py` による自動MOS評価と、人間による聴感テストを併用。

#### 6.3 辞書登録（固有名詞の発音制御）
Style-Bert-VITS2の辞書機能を用いて、以下の固有名詞の読みを事前登録する。
```
ヤチヨ → やちよ
ツクヨミ → つくよみ
ヤオヨロー → やおよろー
やっちょ → やっちょ（一人称）
```

### 7. 推論サーバー（API）の構成

#### 7.1 FastAPIサーバー起動
```bash
python server_fastapi.py --model_path ./model/yachiyo/ --device cuda --port 5000
```

#### 7.2 APIリクエスト仕様
Style-Bert-VITS2はテキスト内容から感情を自動で推論するため、感情パラメータの指定は不要。テキスト本文のみを送信すれば、文脈に応じた声色で音声が生成される。
```python
import requests

response = requests.post("http://localhost:5000/voice", json={
    "text": "ヤオヨロー！今日もいい天気だね！",
    "model_id": 0,           # ヤチヨモデルのID
    "speed": 1.0,            # 再生速度
    "language": "JP"
})

# response.content → WAVバイナリ
```
※ フェーズ1の `<emotion>` XMLタグはフェーズ2（アバター表情制御）専用。TTS側にはタグを除去したプレーンテキストのみを渡す設計とする。

### 8. フェーズ4統合時のVRAM配分計画
```
RTX 3060 (12GB VRAM) の配分:
┌────────────────────────────────┐
│ Ollama LLM (8B Q4_K_M)    ~6GB   │
│ Style-Bert-VITS2 推論    ~2.5GB │
│ OS/ドライバ予約          ~1.5GB │
│ 安全マージン             ~2GB   │
└────────────────────────────────┘
```

### 9. フェーズ3の段階的検証ゴール（R&Dマイルストーン）
- **Step A (データ収集)**: 早見沙織の音声素材を収集・前処理し、品質ゲートを通過したクリーンデータ10分以上を確保する。
- **Step B (学習・評価)**: Style-Bert-VITS2 JP-Extraでファインチューニングを実行し、生成音声のMOSスコアと聴感テストで品質を定量評価する。
- **Step C (API検証)**: FastAPIサーバーとして起動し、Pythonスクリプトからテキストを投げて音声ファイルが正常に返却されることを確認する。
- **Step D (VRAM同居テスト)**: OllamaとStyle-Bert-VITS2を同時起動し、`nvidia-smi` でVRAM消費量を計測。安全マージンが2GB以上あることを定量的に確認する。
