# Yachiyo Extraction Guidelines V1

目的: 文字起こしから、LLMにヤチヨらしいロールプレイをさせるための情報を、再利用しやすい形で抽出する。

## 結論

文字起こしは、台詞集として使うより、`人格制御用データ` として分解するほうが安全で強い。

## 抽出方針

### 1. 文そのものより、振る舞いを抽出する

- 何を大切にしているか
- どう受け止めるか
- どこで冗談に逃がすか
- どこで本音を出すか

この層を先に取る。

### 2. 発話と内心を分ける

- `発話`: 会話見本に使える可能性がある
- `内心`: 人格理解には重要だが、そのまま会話へ入れると壊れやすい

### 3. モードで分ける

- `public`
- `private`
- `deep`
- `inner`

人格は1枚岩ではなく、モードを切り替えるものとして扱う。

### 4. 危険な例を明示的に分ける

`safe_for_prompt = yes / caution / no` を最初から付ける。  
よい資料と危ない資料を混ぜない。

## 文字起こしから取るべき情報

- 価値観
- 話し方の温度
- 語尾や間投詞
- 相手との距離感
- 感情の出し方
- 冗談と本音の切り替え位置
- 抽象語と具体語の混ぜ方
- 何を避けているか

## 文字起こしからそのまま取らないほうがいいもの

- 印象的な決め台詞の反復
- 文脈依存が強すぎる深層独白
- 演劇性の高い断片
- 1回しか出ない強すぎる言い回し

## 外部ノウハウを踏まえた運用原則

### A. 人格は上位指示に置く

OpenAIのガイドでは、高レベルな振る舞いは `instructions` や `developer` 側に置く考え方が明示されている。  
つまり、人格は毎ターンのユーザー入力に混ぜるより、上位の永続ルールとして持たせたほうが安定する。

### B. モデルごとの差を前提にする

OpenAIもAnthropicも、モデルやスナップショットごとに出力の癖が変わるので、プロンプトは固定物ではなく評価対象として扱うべきだとしている。  
ヤチヨ人格も、`モデルを変えても同じように出るはず` とは考えない。

### C. 声の再現より、分布の制御として考える

研究では、persona steerability は単発の良い返答ではなく、複数サンプルで見た時にどのくらい振る舞い分布が変わるかで評価されている。  
つまり、目指すべきは「毎回同じ台詞」ではなく、「毎回違うが、同じ人格原理で返している」状態。

### D. データ駆動の persona は強い

研究では、雑な属性指定より、データから抽出した persona のほうが steerability が高いという報告がある。  
ヤチヨでも、`歌姫っぽく` のような雑な指示より、文字起こしから作った価値観・態度・モードのセットのほうが効く可能性が高い。

### E. eval を先に作る

人格設計は、作ってから感覚で判断すると壊れやすい。  
先に日常会話の評価セットを置いて、自然さ・反復・不気味さ・会話継続性を見たほうがよい。

## 実務向けパイプライン

1. 文字起こしを `1発話` 単位で切る
2. 長文だけ節分割する
3. `mode / speech_act / target / emotion / safe_for_prompt` を付ける
4. `yes` 群から会話見本候補を作る
5. `caution` 群からルールだけを抽出する
6. `no` 群は人格理解専用にする
7. そこから `persona core` と `style rules` を作る
8. 日常入力で複数回評価する
